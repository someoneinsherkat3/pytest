# Hook

##  Hook

‏pytest در طول اجرا چند **مرحله** دارد:
- راه‌اندازی
- جمع‌آوری تست‌ها
- اجرای هر تست
- گزارش
- پایان
در هر مرحله، pytest تابعی با **نام ثابت** را صدا می‌زند،  به این توابع **hook** می‌گویند. ما با تعریف کردن تابعی با همان نام، خود را به آن مرحله «وصل» می‌کنیم.

درست مثل override کردن متد ها در OOP ولی اینجا کلاس نداریم و صرفا توابع مشخصی هستند که عملکرد انها را توسعه و تغییر میدهیم  .
در واقع کاری که ما انجام میدهیم این است که یک تابع دقیقا با همان نام که pytest قرارداد کرده در فایل  `conftest.py`  مینویسیم . خود pytest ان را به عنوان hook در نظر میگیرد و در زمان خودش اجرا میکند.
هر hook  یک لحظه مشخص دارد؛ مثلاً `pytest_sessionstart` یعنی «لحظه شروع اجرا».


قواعد:
- نام باید دقیقاً همان نام hook باشد (با پیشوند `_pytest`).
- لازم نیست همه پارامترها را بنویسیم؛ فقط آن‌هایی را مینویسم که لازم داریم. pytest بر اساس **نام** پارامترها آن‌ها را می‌دهد.
- ثبت جداگانه لازم نیست؛ تعریف در `conftest.py` یا پلاگین کافی است.


> نکته: بعضی hookها فقط در `conftest.py` ریشه یا پلاگین کار می‌کنند، چون خیلی زود صدا زده می‌شوند (مثل `pytest_addoption`).

## pytest and hook execution cycle  

به ترتیب زمانی:

```
۱. راه‌اندازی (Initialization)
   pytest_addoption                ← تعریف گزینه خط فرمان
   pytest_configure                ← پایان تنظیمات اولیه
   pytest_sessionstart             ← session شروع 
   pytest_report_header            ← سربرگ گزارش

۲. جمع‌آوری (Collection)
   pytest_ignore_collect           ← این مسیر نادیده گرفته شود؟
   pytest_collect_file             ← این فایل جمع‌آوری شود؟
   pytest_pycollect_makeitem       ← این شیء تست است؟
   pytest_generate_tests           ← ساخت پارامترها (  پویا parametrize )
   pytest_collection_modifyitems   ← تغییر لیست نهایی تست‌ها
   pytest_collection_finish

۳. اجرا (Run) — برای هر تست
   pytest_runtest_logstart
   pytest_runtest_setup            ← ساخت fixtureها
   pytest_runtest_call             ← اجرای خود تست
   pytest_runtest_teardown         ← پاک‌سازی fixtureها
   pytest_runtest_makereport       ← ساخت شیء گزارش
   pytest_runtest_logreport
   pytest_runtest_logfinish

۴. پایان
   pytest_sessionfinish            ← پایان session
   pytest_terminal_summary         ← اضافه کردن به خلاصه پایانی
   pytest_unconfigure
```

## simple test
یک فایل `conftest.py` با محتوای زیر میسازیم
```python
def pytest_sessionstart(session):
    print("\n>>> pytest started")
    
def pytest_sessionfinish(session, exitstatus):
    print("\n>>> pytest finished")
```

هر hook پارامترهای **خودش** را دارد، با **نام ثابت**.  نمی‌توان نام پارامترها را عوض کرد، چون pytest آن‌ها را **بر اساس نام** پیدا می‌کند و تحویل می‌دهد.

>میتوان هیچ پارامتری هم استفاده نکرد.م 


```python
def pytest_sessionstart():
    print("\n>>> pytest started")
    
def pytest_sessionfinish():
    print("\n>>> pytest finished")
```

>حتی ترتیب نوشتن هم مهم نیست.

```python
def pytest_sessionfinish(session, exitstatus):
    print("\n>>> pytest finished")


def pytest_sessionfinish(exitstatus, session):
    print("\n>>> pytest finished")
```

## `session` , `config` Objects
این‌ها شیءهایی هستند که pytest ارائه می‌دهد تا بتوان **وضعیت اجرا** را مشاهده کرد.
شیء `session`  : خود این اجرای pytest .چند تست پیدا شد، چند تا fail شد
شیء `config` : تنظیمات و گزینه‌های این اجرا. چه گزینه‌هایی اعمال شده ،  `rootdir` کجاست، کدام فایل ini خوانده شد

```python

def pytest_configure(config):
    print("\nrootdir:", config.rootpath)
    print("foncig file:", config.inipath)
    print("CLI args:", config.args)
    print("-v switch:", config.getoption("verbose"))
    

def pytest_sessionfinish(session, exitstatus):
    print("\n number of founded tests:", session.testscollected)
    print("failed tests:", session.testsfailed)
    print("exit code :", exitstatus)
```
تابع `pytest_configure` یک hook  است که فقط `config` می‌گیرد و بعد از تنظیمات اولیه، یک‌بار صدا زده می‌شود.

در `pytest_sessionstart` هنوز جمع‌آوری انجام نشده، پس `session.testscollected` همان‌جا صفر است. در `pytest_sessionfinish` همه عددها نهایی‌اند.

درباره `exitstatus`: نوع آن یک `ExitCode` است و ممکن است چیزی مثل `ExitCode.TESTS_FAILED` چاپ شود. اگر عدد خالص بخواهیم باید `int(exitstatus)` بزنیم.


## important hooks

### `pytest_collection_modifyitems`
اولین hook کاربردی.
بعد از اینکه pytest همه تست‌ها را **پیدا کرد** و قبل از اینکه **اجرا** کند، لیست را به می‌دهد تا هر تغییری خواستیم در آن بدهیم.


پارامترها
```python
def pytest_collection_modifyitems(session, config, items): ...
```

| پارامتر   | معنی                                 |
| --------- | ------------------------------------ |
| `items`   | **لیست** تست‌های پیدا شده (مهم‌ترین) |
| `config`  | تنظیمات اجرا (همان قدم ۲)            |
| `session` | شیء اجرا                             |

مثل قبل فقط آن‌هایی را بنویسیم که لازم داریم. بیشتر وقت‌ها `items` کافی است.

#### هر عضو `items` چیست؟

هر عضو یک شیء **تست** (`item`) است. چند چیز مفید دارد:

| چیز                               | معنی                                         |
| --------------------------------- | -------------------------------------------- |
| `item.name`                       | نام تست، مثل `test_add`                      |
| `item.nodeid`                     | نام کامل، مثل `test_a.py::test_add`          |
| `item.keywords`                   | نام‌ها و markerهای تست                       |
| `item.add_marker(...)`            | اضافه کردن marker به آن تست                  |
| `item.get_closest_marker("slow")` | اگر marker داشت خودش را می‌دهد، وگرنه `None` |

#### see tests  list

```python
# conftest.py
def pytest_collection_modifyitems(items):
    print("\n number of founded tests:")
    for item in items:
        print("  ", item.nodeid)
```

```python
# test_a.py
def test_b(): pass
def test_a(): pass
def test_c(): pass
```

```bash
pytest -s
```

لیست را به همان ترتیبی خروجی میدهد که pytest پیدا کرده (ترتیب نوشتن در فایل: `test_b`، `test_a`، `test_c`).

#### reorder tests

چون `items` یک لیست پایتونی معمولی است، می‌توان آن را مرتب کرد. دقت شود که باید **همان لیست  تغییر داده شود** (نه یک لیست جدید ساخته شود):

```python
def pytest_collection_modifyitems(items):
    items.sort(key=lambda item: item.name)      # مرتب بر اساس نام
```

حالا ترتیب اجرا `test_a`، `test_b`، `test_c` می‌شود. با `pytest -v` میشود بررسی کرد.

اگر نوشتیم `(...)items = sorted` فقط یک متغیر محلی جدید ساخته‌ایم و روی pytest اثری ندارد. برای جایگزین کردن کل لیست از ` ...=[:]items ` استفاده شود.

#### remove a test from run

```python
def pytest_collection_modifyitems(items):
    items[:] = [item for item in items if item.name != "test_b"]
```

‏`test_b` اصلاً اجرا نمی‌شود و در گزارش هم نمی‌آید. (اگر می‌خواستیم در گزارش به‌صورت «رد شده» بیاید، باید به‌جای حذف، marker `skip` اضافه می‌کردیم .)

#### add marker to some tests

```python
import pytest

def pytest_collection_modifyitems(items):
    for item in items:
        if "slow" in item.name:
            item.add_marker(pytest.mark.skip(reason="test is slow"))
```

هر تستی که `slow` در نامش دارد، رد می‌شود. با `pytest -rs` دلیلش را ببین.
