# Marker
‏**Marker** یک برچسب است که با `<pytest.mark.<name@` بالای تست قرار میگیرد تا pytest با آن تست رفتار خاصی داشته باشد، یا بتوانیم تست‌ها را دسته‌بندی کنیم.

برای دیدن لیست تمام maker ها از دستور  زیر استفاده میکنیم:
```bash
➜  pytest --markers

@pytest.mark.filterwarnings(warning): add a warning filter to the given test. see https://docs.pytest.org/en/stable/how-to/capture-warnings.html#pytest-mark-filterwarnings 

@pytest.mark.skip(reason=None): skip the given test function with an optional reason. Example: skip(reason="no way of currently testing this") skips the test.

@pytest.mark.skipif(condition, ..., *, reason=...): skip the given test function if any of the conditions evaluate to True. Example: skipif(sys.platform == 'win32') skips the test if we are on the win32 platform. See https://docs.pytest.org/en/stable/reference/reference.html#pytest-mark-skipif

@pytest.mark.xfail(condition, ..., *, reason=..., run=True, raises=None, strict=strict_xfail): mark the test function as an expected failure if any of the conditions evaluate to True. Optionally specify a reason for better reporting and run=False if you don't even want to execute the test function. If only specific exception(s) are expected, you can list them in raises, and if the test fails in other ways, it will be reported as a true failure. See https://docs.pytest.org/en/stable/reference/reference.html#pytest-mark-xfail

@pytest.mark.parametrize(argnames, argvalues): call a test function multiple times passing in different arguments in turn. argvalues generally needs to be a list of values if argnames specifies only one name or a list of tuples of values if argnames specifies multiple names. Example: @parametrize('arg1', [1,2]) would lead to two calls of the decorated test function, one with arg1=1 and another with arg1=2.see https://docs.pytest.org/en/stable/how-to/parametrize.html for more info and examples.

@pytest.mark.usefixtures(fixturename1, fixturename2, ...): mark tests as needing all of the specified fixtures. see https://docs.pytest.org/en/stable/explanation/fixtures.html#usefixtures 

@pytest.mark.tryfirst: mark a hook implementation function such that the plugin machinery will try to call it first/as early as possible. DEPRECATED, use @pytest.hookimpl(tryfirst=True) instead.

@pytest.mark.trylast: mark a hook implementation function such that the plugin machinery will try to call it last/as late as possible. DEPRECATED, use @pytest.hookimpl(trylast=True) instead.

```



## skip
این تست را رد کن
```python
import pytest

@pytest.mark.skip(reason="not ready yet")
def test_future_feature():
    assert False
```

تست اجرا **نمی‌شود** و در گزارش به‌صورت `SKIPPED` می‌آید. دلیل (`reason`) در گزارش نمایش داده می‌شود.


## skipif

فقط اگر شرط برقرار بود رد کن
ساختارش به این شکل است که ارگمان اول شرط و ارگمان دوم عبارت  دلیل (`reason`) در گزارش نمایش داده می‌شود.

```python
@pytest.mark.skipif(   condition   , reason="  ")
```


```python
import sys

@pytest.mark.skipif(sys.version_info < (3, 10), reason="need python 3.12 or higher")
def test_new_syntax():
    assert True
```

```python
@pytest.mark.skipif(sys.platform == "win32", reason="only on unix base OS")
def test_unix_only():
    assert True
```

## xfail

انتظار دارم این تست فیل شود
مثلا برای برای باگ‌های شناخته‌شده‌ای که هنوز درست نکرده‌ایم یا شرایط خاصی که انتظار داریم خطا دریافت کنیم:
```python
@pytest.mark.xfail(reason="bugg")
def test_known_bug():
    assert 1 + 1 == 3
```


## custom mark
می‌توان  mark  بسازیم و تست‌ها را دسته‌بندی کنیم: 
```python
@pytest.mark.slow
def test_big_calculation():
    assert sum(range(10_000_000)) > 0

@pytest.mark.fast
def test_small():
    assert 1 + 1 == 2
```
و فقط یک دسته را اجرا کنیم:
```bash
➜  pytest -m slow          
➜  pytest -m "not slow"    
➜  pytest -m "slow or fast"
```

سویچ `m-` یک یا چند marker میگیرد و تنها ان ها را اجرا میکند

## register a custom marker
میتوان marker های دلخواه خودمان را بنویسیم
برای ثبت، در `pytest.ini`:
```python
[pytest]
markers =
    slow: slow tests
    fast: fast tests
```

> اگر marker را ثبت نکنیم، pytest هشدار می‌دهد (`PytestUnknownMarkWarning`).

## set marker on all Class tests
با تعریف marker روی یک کلاس ان marker روی تمام تست های ان کلاس (طبق قرار داد نام گذازی) اعمال میشوند.
```python
@pytest.mark.slow
class TestHeavy:
    def test_a(self):
        ...
    def test_b(self):
        ...
    def check(self):
	    ...
```

همچنیم میتوان روی کل فایل با متغیر `pytestmark` در ابتدای فایل marker اعمال کرد
```python
import pytest

pytestmark = pytest.mark.slow

def test_one():
    ...
```


## parametrize with marker
قابلیت`parametrize` هم در واقع یک marker است. می‌توان روی یک ردیف خاص marker بگذارد:
```python
@pytest.mark.parametrize("n, expected", [
    (2, 4),
    (3, 9),
    pytest.param(4, 15, marks=pytest.mark.xfail(reason="on perpose false")),
])
def test_square(n, expected):
    assert n * n == expected
```
