# Fixture 

‏**Fixture** تابعی است که **قبل از تست** اجرا می‌شود، چیزی را **آماده می‌کند** (داده، فایل، اتصال و...) و نتیجه را به تست **تحویل می‌دهد**. اگر لازم باشد، **بعد از تست** هم آن را جمع می‌کند.



فرض کنید چند تست همه به یک لیست از اعداد نیاز دارند. به‌جای ساختن لیست در هر تست، یک‌بار در fixture می‌سازی:

```python
import pytest

@pytest.fixture
def numbers():
    return [1, 2, 3]

def test_length(numbers):
    assert len(numbers) == 3

def test_sum(numbers):
    assert sum(numbers) == 6
```


1. بالای تابع `numbers` عبارت `pytest.fixture@` را نوشتیم. این یعنی «این تابع یک fixture است».
2. در تست، از پارامتری به نام `numbers` استفاده شده (`def test_length(numbers)`).
3. ‏pytest می‌بیند نام پارامتر با نام یک fixture یکی است، پس **خودش** تابع `numbers` را اجرا می‌کند و مقدار برگشتی (`[1, 2, 3]`) را به تست می‌دهد.

لازم نیست دستی fixture را صدا بزنیم. فقط **نامش را به‌عنوان پارامتر می نویسیم**.

## نمونه های پراستفاده fixture

### `tmp_path`
برای تستی که با فایل کار می‌کند. pytest یک پوشه موقت و یکتا می‌سازد ما داخلش فایل می‌سازیم بدون اینکه فایل‌های واقعی را خراب کنیم.
```python
def test_write_file(tmp_path):
    p = tmp_path / "a.txt"      # dir to temp files
    p.write_text("hello")
    assert p.read_text() == "hello"
```

‏`tmp_path` یک شیء `Path` (از `pathlib`) است.
عملگر `/` مسیرها را به هم وصل می‌کند.
هر تست پوشه مخصوص خودش را دارد، و پوشه‌های قدیمی خودکار پاک می‌شوند.
```python
def save_data(path, data):
    with open(path, "w") as f:
        f.write(data)

def test_save_data(tmp_path):
    p = tmp_path / "name.txt"
    save_data(p, "log ... ")
    assert p.read_text() == "log ... "
```


‏`tmp_path` یک پوشه واقعی روی دیسک است که pytest برای هر تست می‌سازد. مسیر پایه‌اش در لینوکس معمولاً داخل `/tmp` است:
```
/tmp/pytest-of-<user>/pytest-<test-name>/<number of run0>

/tmp/pytest-of-ali/pytest-3/test_write_file0/
```

اگر با سویچ `setup-show--` تست را اجرا کنیم مسیری که pytest در نظر گرفته را میبینیم
```bash

```

میتاون مسیر پایه را تغییر داد 
```bash
pytest --basetemp=./my_tmp
```
این گزینه پوشه پایه را عوض می‌کند و **هر بار محتوای قبلی آن را پاک می‌کند**. پس مسیری که برایش مهم است را نباید داد.

### `capsys`
برای تست تابعی که چیزی **چاپ** می‌کند:
```python
def greet(name):
    print(f"Hello {name}")

def test_greet(capsys):
    greet("Ali")
    captured = capsys.readouterr()
    assert captured.out == "Hello Ali\n"
```
- ‏`capsys.readouterr()` هر چیزی را که تا آن لحظه چاپ شده برمی‌گرداند.
- ‏`.out` خروجی عادی (`stdout`) و `.err` خروجی خطا (`stderr`) است.
- آخر `print` همیشه یک `\n` هست، برای همین در مقایسه آمده.


### `monkeypatch`
برای اینکه **موقتاً** یک متغیر، تابع یا متغیر محیطی را عوض کنیم. بعد از تست، همه‌چیز **خودکار به حالت اول برمی‌گردد**.
```python
import os

def get_mode():
    return os.environ.get("MODE", "normal")

def test_mode(monkeypatch):
    monkeypatch.setenv("MODE", "debug")
    assert get_mode() == "debug"

def test_mode_default(monkeypatch):
    monkeypatch.delenv("MODE", raising=False)
    assert get_mode() == "normal"
```


جایگزین کردن یک تابع

فرض کن تابعی داری که به ساعت واقعی وابسته است و می‌خواهی نتیجه‌اش ثابت باشد:
```python
import time

def is_morning():
    return time.localtime().tm_hour < 12

def test_morning(monkeypatch):
    class FakeTime:
        tm_hour = 8
    monkeypatch.setattr(time, "localtime", lambda: FakeTime())
    assert is_morning() is True
    
```

- ‏`monkeypatch.setattr(شیء, "نام", مقدار_جدید)` یعنی «در این شیء، این نام را موقتاً با مقدار جدید عوض کن».
- بعد از پایان تست، `time.localtime` دوباره همان اصلی می‌شود.

تغییر مقدار در دیکشنری
```python
def test_config(monkeypatch):
    config = {"debug": False}
    monkeypatch.setitem(config, "debug", True)
    assert config["debug"] is True
```

خلاصه متدهای پرکاربرد:

|متد|کار|
|---|---|
|`setattr(obj, "name", value)`|عوض کردن یک ویژگی یا تابع|
|`setenv("NAME", "value")`|تنظیم متغیر محیطی|
|`delenv("NAME", raising=False)`|حذف متغیر محیطی|
|`setitem(dict, key, value)`|عوض کردن یک کلید دیکشنری|
|`chdir(path)`|تغییر پوشه جاری|

###  `caplog`
برای تستی که باید مطمئن شوی تابع **لاگ** می‌نویسد:


```python
import logging

def process():
    logging.warning("something is wrong")

def test_log(caplog):
    process()
    assert "something is wrong" in caplog.text
```

- ‏`caplog.text` همه متن لاگ‌هاست.
- ‏`caplog.records` لیست رکوردهای لاگ (با `.levelname` و `.message`) است.

## ترکیب چند fixture

یک تست می‌تواند چند fixture را با هم بگیرد:

```python
def test_combo(tmp_path, capsys):
    p = tmp_path / "x.txt"
    p.write_text("data")
    print(p.read_text())
    assert capsys.readouterr().out == "data\n"
```





## لیست fixtureهای آماده pytest

برای دیدن لیست دقیق نسخه خودت (با توضیح هر کدام):

```bash
pytest --fixtures
```

‏fixtureهایی که با `_` شروع می‌شوند فقط با `v-` نشان داده می‌شوند. در ادامه موارد مهم، دسته‌بندی‌شده می‌آید. اگر مقدار پیش‌فرض (scope) را ذکر نشده بود، `function` است.

### ۱. فایل و پوشه

| fixture            | scope    | کاربرد                                                                                      |
| ------------------ | -------- | ------------------------------------------------------------------------------------------- |
| `tmp_path`         | function | یک پوشه موقت یکتا برای هر تست (شیء `pathlib.Path`)                                          |
| `tmp_path_factory` | session  | ساخت پوشه‌های موقت دلخواه در fixtureهای با scope بزرگ‌تر: `tmp_path_factory.mktemp("name")` |
| `tmpdir`           | function | همان `tmp_path` ولی با نوع قدیمی `py.path.local`. برای کد جدید `tmp_path` استفاده شود       |
| `tmpdir_factory`   | session  | نسخه قدیمی `tmp_path_factory`                                                               |

### ۲. گرفتن خروجی

| fixture        | کاربرد                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------- |
| `capsys`       | گرفتن `stdout` و `stderr` به‌صورت متن: `capsys.readouterr()`                                |
| `capsysbinary` | مثل `capsys` ولی خروجی به‌صورت `bytes`                                                      |
| `capfd`        | مثل `capsys` ولی در سطح file descriptor (خروجی برنامه‌های بیرونی و کدهای C هم گرفته می‌شود) |
| `capfdbinary`  | مثل `capfd` با `bytes`                                                                      |
| `caplog`       | گرفتن لاگ‌ها: `caplog.text`، `caplog.records`، `caplog.set_level(...)`                      |

### ۳. تغییر موقت محیط

| fixture       | کاربرد                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------- |
| `monkeypatch` | تغییر موقت ویژگی، تابع، دیکشنری، متغیر محیطی، پوشه جاری، `sys.path` و برگشت خودکار بعد از تست |

متدهای `monkeypatch`:

| متد                          | کار                           |
| ---------------------------- | ----------------------------- |
| `setattr(obj, name, value)`  | عوض کردن ویژگی یا تابع        |
| `delattr(obj, name)`         | حذف ویژگی                     |
| `setitem(dict, key, value)`  | عوض کردن کلید دیکشنری         |
| `delitem(dict, key)`         | حذف کلید                      |
| `setenv(name, value)`        | تنظیم متغیر محیطی             |
| `delenv(name, raising=True)` | حذف متغیر محیطی               |
| `syspath_prepend(path)`      | اضافه کردن مسیر به `sys.path` |
| `chdir(path)`                | عوض کردن پوشه جاری            |
| `context()`                  | استفاده موقت داخل بلوک `with` |

### ۴. اطلاعات درباره تست در حال اجرا

| fixture        | کاربرد                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `request`      | اطلاعات تست و fixture فعلی: `request.param` (برای fixture پارامتری)، `request.node` (نام تست و markerها)، `request.config`، `request.addfinalizer(fn)` |
| `pytestconfig` | دسترسی به تنظیمات pytest (`pytestconfig.getoption("verbose")`، `rootpath`)                                                                             |
| `cache`        | ذخیره داده بین اجراهای مختلف pytest: `cache.get("key", default)` و `cache.set("key", value)`                                                           |

### ۵. ثبت اطلاعات اضافی در گزارش

|fixture|scope|کاربرد|
|---|---|---|
|`record_property`|function|افزودن یک ویژگی به گزارش XML: `record_property("key", value)`|
|`record_xml_attribute`|function|افزودن attribute به تگ `testcase` در XML|
|`record_testsuite_property`|session|افزودن ویژگی به کل suite در گزارش XML|

### ۶. بررسی هشدار و خطا

|fixture|کاربرد|
|---|---|
|`recwarn`|ثبت هشدارهای ایجادشده در تست: `recwarn.list`، `recwarn.pop(...)` (معادل `pytest.warns` ولی به‌صورت fixture)|
|`subtests`|اجرای چند بررسی مستقل داخل یک تست که هر کدام جدا گزارش شوند (در نسخه‌های جدید pytest موجود است)|

### ۷. fixtureهای مخصوص `unittest`

‏fixtureهای خودکاری که برای کلاس‌های `unittest.TestCase` ساخته می‌شوند (با نام‌هایی مثل `_unittest_setUpClass_fixture_...`)، و فقط
با `fixtures -v--` دیده می‌شوند. لازم نیست با آن‌ها کار کنیم.



```python
def test_examples(tmp_path, capsys, caplog, monkeypatch, request, pytestconfig):
    # tmp_path: فایل موقت
    (tmp_path / "a.txt").write_text("hi")

    # capsys: خروجی print
    print("hello")
    assert capsys.readouterr().out == "hello\n"

    # caplog: لاگ
    import logging
    logging.warning("warn")
    assert "warn" in caplog.text

    # monkeypatch: متغیر محیطی
    monkeypatch.setenv("X", "1")

    # request: نام تست
    assert request.node.name == "test_examples"

    # pytestconfig: پوشه ریشه
    print(pytestconfig.rootpath)
```

مثال `cache` (مقدار بین دو اجرا باقی می‌ماند):

```python
def test_counter(cache):
    n = cache.get("my/counter", 0)
    cache.set("my/counter", n + 1)
    print(n)
```

مثال `recwarn`:

```python
import warnings

def test_warn(recwarn):
    warnings.warn("old", DeprecationWarning)
    assert len(recwarn) == 1
    assert recwarn[0].category is DeprecationWarning
```



«مقدار پیش‌فرض» این fixtureها معمولاً scope آن‌هاست (جدول بالا). مقدار برگشتی هر کدام یک شیء است و عدد یا رشته ثابت نیست. fixtureهای آماده فقط همین‌ها هستند؛ `db` و `client` و مانند آن‌ها **جزو pytest نیستند** و از پلاگین‌ها می‌آیند.
