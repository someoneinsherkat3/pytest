# write custom fixture 

برای منطقی که مخوایم نقش fixture را داشته باشد یک تابع می نویسیم .
برای ان تابع یک decorator به اسم `pytest.fixture@` قرار میدهیم و دیگه نیازی به این در فایل کانفیگ pytest چیزی را ثبت کنیم نیست.
‏pytest موقع اجرا خودش **جستجو** می‌کند  وقتی تستی پارامتری به نام `user` دارد، pytest به ترتیب این جاها را نگاه می‌کند و اولین fixture هم‌نام را برمی‌دارد:
1. **همان کلاس تست** (اگر تست داخل کلاس است)
2. **همان فایل تست** (ماژول)
3. ‏ **`conftest.py`** هم‌پوشه با تست
4.  ‏ **`conftest.py` پوشه‌های بالاتر** تا ریشه
5. **پلاگین‌ها** (مثل `pytest-django` که `db` و `client` را می‌دهد)
6. ‏ **fixtureهای داخلی pytest** (`tmp_path` و...)

یعنی «ثبت کردن fixture» فقط به معنای **گذاشتن fixture در جای درست** است.



```python
import pytest

@pytest.fixture
def user():
    return {"name": "Ali", "age": 20}

def test_name(user):
    assert user["name"] == "Ali"
```

```python
@pytest.fixture
def db_file(tmp_path):
    path = tmp_path / "db.txt"
    path.write_text("start")
    print("initial")
    yield path
    print("clean up")

def test_read(db_file):
    assert db_file.read_text() == "start"
```

با سویچ `s-` اجرا شود تا ترتیب چاپ‌ها را قابل مشاهده باشد.

## `fixture` in `fixture`
 ‏fixture که fixture دیگر می‌گیرد:

```python
@pytest.fixture
def config(tmp_path):
    f = tmp_path / "config.ini"
    f.write_text("mode=debug")
    return f

@pytest.fixture
def app(config):
    return {"config_path": config, "started": True}

def test_app(app):
    assert app["started"]
```

‏pytest خودش ترتیب ساخت را (`tmp_path` ← `config` ← `app`) تشخیص می‌دهد.

## `scope`

میتوان scope هر fixture را تعیین کرد :

```python
@pytest.fixture(scope="module")
def expensive():
    print("ساخته شد")
    return [1, 2, 3]
```

| scope                | ساخته می‌شود برای |
| -------------------- | ----------------- |
| `function` (پیش‌فرض) | هر تست            |
| `class`              | هر کلاس           |
| `module`             | هر فایل           |
| `package`            | هر پکیج           |
| `session`            | کل اجرا           |

قانون: fixture با scope بزرگ‌تر **نمی‌تواند** fixture با scope کوچک‌تر را بگیرد (مثلاً `session` نمی‌تواند `tmp_path` را بگیرد؛ به همین دلیل از `tmp_path_factory` استفاده شده ).

> اگر fixture با scope بزرگ‌تر داده قابل تغییر (لیست، دیکشنری) برگرداند و یک تست آن را تغییر دهد، تست‌های بعدی تغییر را می‌بینند.


## `autouse`
با `autouse` بدون اینکه تست آن را در پارامترها بنویسد، برای همه تست‌های scopeش اجرا می‌شود:

```python
@pytest.fixture(autouse=True)
def log_test(request):
    print(f"شروع {request.node.name}")
    yield
    print(f"پایان {request.node.name}")
```

مثلا برای پاک‌سازی عمومی، تنظیم متغیر محیطی برای همه تست‌ها:

```python
@pytest.fixture(autouse=True)
def fake_env(monkeypatch):
    monkeypatch.setenv("APP_MODE", "test")
```

## ۶. `params`: fixture پارامتری

```python
@pytest.fixture(params=["a.txt", "b.txt", "c.txt"])
def filename(request):
    return request.param

def test_ext(filename):
    assert filename.endswith(".txt")
```

## `name`
برای ان که نام fixture را تغییر دهیم:
```python
@pytest.fixture(name="u")
def create_user_fixture():
    return {"name": "Ali"}

def test_x(u):
    assert u["name"] == "Ali"
```



## `request.addfinalizer`

```python
@pytest.fixture
def resource(request):
    r = open_something()
    request.addfinalizer(lambda: r.close())
    return r
```

استفاده از ‏`yield` معمولاً خواناتر است؛ این روش وقتی به درد می‌خورد که چند پاک‌سازی مستقل داریم.

##  fixture as factory

وقتی تست خودش می‌خواهد **چند شیء با مقدارهای دلخواه** بسازد، fixture یک **تابع** برمی‌گرداند:

```python
@pytest.fixture
def make_user():
    created = []
    def _make(name="Ali", age=20):
        user = {"name": name, "age": age}
        created.append(user)
        return user
    yield _make
    created.clear()          # پاک‌سازی همه ساخته‌شده‌ها

def test_users(make_user):
    a = make_user()
    b = make_user("Sara", 30)
    assert a["name"] == "Ali"
    assert b["age"] == 30
```

## `conftest.py`

‏fixtureهای داخل `conftest.py` بدون import در همه تست‌های همان پوشه و زیرپوشه‌ها در دسترس‌اند:

```
tests/
├── conftest.py        ← fixtureهای مشترک همه
├── test_a.py
└── sub/
    ├── conftest.py    ← فقط برای تست‌های sub
    └── test_b.py
```

اگر دو fixture هم‌نام باشند، نزدیک‌ترین به تست (پایین‌ترین `conftest.py` یا خود فایل) برنده است و می‌توانی fixture بالاتر را **override** کنی.

## sample

```python
import pytest

@pytest.fixture(scope="session")
def base_data():
    return {"version": 1}              # فقط یک‌بار ساخته می‌شود

@pytest.fixture
def workdir(tmp_path):
    d = tmp_path / "work"
    d.mkdir()
    yield d
    print("پایان کار با", d)

@pytest.fixture(autouse=True)
def quiet_env(monkeypatch):
    monkeypatch.setenv("LANG", "C")

@pytest.fixture
def make_file(workdir):
    def _make(name, text=""):
        p = workdir / name
        p.write_text(text)
        return p
    return _make

def test_files(make_file, base_data):
    f = make_file("a.txt", "hi")
    assert f.read_text() == "hi"
    assert base_data["version"] == 1
```



```bash
pytest --fixtures          # لیست fixtureها
pytest --setup-show        # ترتیب ساخت و پاک شدن (همان که قبلاً استفاده کردی)
pytest --setup-plan        # فقط نشان بده چه می‌شد، اجرا نکن
```
