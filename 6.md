#  `request` fixture
مشکل:
‏fixture یک تابع جداست. تست‌ها آن را می‌خواهند و pytest آن را صدا می‌زند.
```python
import pytest

@pytest.fixture
def who():
    return "???"

def test_a(who):
    print(who)

def test_b(who):
    print(who)
```

دو تست مختلف همین fixture را گرفته‌اند، ولی داخل `who` راهی نیست که بفهمی **چه کسی** او را خواسته. fixture فقط یک تابع است و ورودی ندارد.

راه‌حل:
‏pytest به fixture یک **«برگه اطلاعات»** می‌دهد که نامش `request` است. این هم یک fixture آماده است و دقیقاً مثل بقیه گرفته می‌شود: **نامش را به‌عنوان پارامتر مینویسم.** 

```python
import pytest

@pytest.fixture
def who(request):                  # only add request
    return request.node.name

def test_a(who):
    print(who)

def test_b(who):
    print(who)
```

اجرا که بکنیم : 
```bash
pytest -s
```
خروجی:
```
test_a
test_b
```
‏`request` یک fixture است، ولی هر تستی که آن را بخواهد جواب متفاوتی می‌گیرد، چون `request` می‌داند چه کسی درخواست کرده.




###  `request.node`

‏ `request.node` همان **تستی** است که درخواست داده. 
حالا بررسی کنیم این شیء چه چیزهایی دارد.
با این‌ Objectها fixture می‌تواند رفتارش را بر اساس تست عوض کند.

#### name ,  nodeid

```python
def test_hello(request):
    print(request.node.name)      # test_hello
    print(request.node.nodeid)    # test_file.py::test_hello
```

| object   | معنی                                                                  |
| -------- | --------------------------------------------------------------------- |
| `name`   | فقط نام تست                                                           |
| `nodeid` | نشانی کامل: فایل + (کلاس) + تست. همان چیزی که با `pytest -v` می‌بینیم |

#### read from markers

```python
import pytest

@pytest.mark.color("red")
def test_a(request):
    m = request.node.get_closest_marker("color")
    print(m)
```

‏`("نام")get_closest_marker` دو حالت دارد:

- اگر تست آن marker را داشته باشد، خود marker را می‌دهد.
- اگر نداشته باشد، `None` می‌دهد.

از marker می‌توان آرگومان‌هایش را خواند:

```python
m = request.node.get_closest_marker("color")
print(m.args)        # ('red',)   آرگومان‌های بدون نام
print(m.kwargs)      # {}         آرگومان‌های نام‌دار
```

کلمه «closest» (نزدیک‌ترین) یعنی اگر marker هم روی تابع و هم روی کلاس یا فایل باشد، نزدیک‌ترین یعنی همان که روی خود تابع است را برمی‌گرداند.

#### use fixture combine with marker 

‏fixtureای که رنگ را از marker هر تست می‌گیرد و اگر marker نبود، رنگ پیش‌فرض می‌دهد:

```python
import pytest

@pytest.fixture
def color(request):
    m = request.node.get_closest_marker("color")
    if m is None:
        return "white"
    return m.args[0]

@pytest.mark.color("red")
def test_red(color):
    assert color == "red"

def test_default(color):
    assert color == "white"
```

یک fixture است، ولی هر تست از طریق **marker خودش** به آن اطلاعات می‌دهد. این نوع الگو خیلی رایج است.

برای اینکه هشدار marker ناشناخته نگیرد، باید آن را در `pytest.ini` ثبت کرد:

```ini
[pytest]
markers =
    color: .....
```

#### add marker to a test from request fixture

با ‏`(...)request.node.add_marker`  میتوان در لحظه اجرا  تست  به ان marker اضافه کرد:

```python
def test_x(request):
    request.node.add_marker(pytest.mark.xfail(reason="باگ"))
    assert False       # فیل می‌شود ولی xfail حساب می‌شود
```


---


‏`request` یک fixture آماده است که **اطلاعات درباره همین لحظه اجرا** را می‌دهد: «این تست کدام است؟ این fixture کجا صدا زده شده؟ مقدار پارامتر فعلی چیست؟ تنظیمات چیست؟»

مثل یک **کارت شناسایی** است. هر بار که تستی (یا fixtureای) اجرا می‌شود، pytest یک کارت درباره آن می‌سازد و از طریق `request` در اختیار قرار می‌دهد. ما فقط نامش را به‌عنوان پارامتر می‌نویسیم:

```python
def test_x(request):
    print(request.node.name)
```

## `request.param` use to send parameter

فقط داخل fixtureای که `params` دارد کار می‌کند:

```python
@pytest.fixture(params=[1, 2, 3])
def number(request):
    return request.param
```

اگر fixture `params` نداشته باشد، `request.param` وجود ندارد و خطا می‌دهد.

## `request.node`
خود تست (یا ماژول، کلاس) را نگه میدارد :
```python
def test_info(request):
    print(request.node.name)       # test_info
    print(request.node.nodeid)     # test_a.py::test_info
```

این همان شیء `item` است که در hookها بررسی میشود. چند کاربرد مهم:

```python
request.node.get_closest_marker("slow")     # marker را بخوان (None اگر نبود)
request.node.add_marker(pytest.mark.xfail)  # marker اضافه کن
```

نکته: `request.node` به **scope** آن  fixture بستگی دارد.

| scope fixture | `request.node` چیست |
| ------------- | ------------------- |
| `function`    | خود تست             |
| `class`       | کلاس                |
| `module`      | فایل                |
| `session`     | کل اجرا             |

## `request.config`
تنظیمات 
همان `config` قدم ۲ hookها:

```python
request.config.getoption("--env")       # گزینه خط فرمان
request.config.getini("testpaths")      # مقدار از pytest.ini
request.config.rootpath                 # rootdir
```

## ۴. اطلاعات محل اجرا

|چیز|معنی|
|---|---|
|`request.fixturename`|نام fixtureای که الان داخلش هستی|
|`request.scope`|scope آن fixture، مثلاً `"function"`|
|`request.function`|تابع تست (فقط در fixtureهای function-scope)|
|`request.module`|ماژول (فایل) تست|
|`request.cls`|کلاس تست (اگر تست داخل کلاس نباشد `None`)|
|`request.instance`|نمونه کلاس تست (اگر کلاس نباشد `None`)|
|`request.path`|مسیر فایل تست (`pathlib.Path`)|

مثال: fixtureای که برای هر تست یک پوشه به نام خود آن تست می‌سازد:

```python
@pytest.fixture
def workdir(tmp_path, request):
    d = tmp_path / request.node.name
    d.mkdir()
    return d
```

## ۵. `request.addfinalizer`: ثبت پاک‌سازی

جایگزین `yield` برای پاک‌سازی:

```python
@pytest.fixture
def resource(request):
    print("ساخته شد")
    def cleanup():
        print("پاک شد")
    request.addfinalizer(cleanup)
    return "data"
```

`cleanup` بعد از تست صدا زده می‌شود، حتی اگر تست فیل شود. می‌توانی چند finalizer ثبت کنی؛ به ترتیب **معکوس** اجرا می‌شوند.

## ۶. `request.getfixturevalue("نام")`: گرفتن fixture دیگر با نام (پویا)

تا حالا fixtureها را با **نوشتن نام در پارامتر** می‌گرفتی. گاهی نام را تا لحظه اجرا نمی‌دانی (مثلاً از `params` می‌آید). آن‌جا:

```python
@pytest.fixture(params=["tmp_path", "tmp_path_factory"])
def which(request):
    return request.getfixturevalue(request.param)
```

یا حالت ساده‌تر: داخل تست، فقط اگر شرطی برقرار بود fixtureی را بخواه:

```python
def test_x(request):
    if request.config.getoption("--env") == "prod":
        db = request.getfixturevalue("prod_db")
```

محدودیت: داخل مرحله پاک‌سازی (بعد از `yield` یا داخل finalizer) نمی‌توانی با `getfixturevalue` fixture جدید بخواهی.

## ۷. `request.applymarker`: افزودن marker در لحظه اجرا

```python
def test_x(request):
    if something_wrong():
        request.applymarker(pytest.mark.xfail(reason="مشکل شناخته‌شده"))
    assert ...
```

## آزمایش

```python
# test_request.py
import pytest

@pytest.fixture
def info(request):
    print("\nfixture:", request.fixturename)
    print("scope:", request.scope)
    print("node:", request.node.name)
    print("module:", request.module.__name__)
    print("class:", request.cls)

def test_a(info):
    pass

class TestB:
    def test_b(self, info):
        pass
```

```bash
pytest -s
```

ببین برای `test_a` مقدار `class: None` است ولی برای `test_b` نام کلاس `TestB` می‌آید.
