# `addfinalizer` and  `getfixturevalue`

##  `request.addfinalizer`

### مشکل

‏fixture معمولاً چیزی می‌سازد (فایل، اتصال، پوشه) و بعد از تست باید آن را جمع کند. با `return` نمی‌شود این کار را کرد  چون بعد از `return` دیگر کدی اجرا نمی‌شود.

### راه‌حل: تابع پاک‌سازی را به pytest بسپار

```python
import pytest

@pytest.fixture
def res(request):
    print("\n crteated")

    def cleanup():
        print("cleaned up")

    request.addfinalizer(cleanup)
    return "data"

def test_a(res):
    print("test running")
```

```bash
pytest -s
```

خروجی:

```
crteated
test running
cleaned up
```

‏`addfinalizer(fn)` یعنی «این تابع را به یاد داشته باش و بعد از پایان تست صدایش بزن». حتی اگر تست fail شود، `cleanup` اجرا می‌شود.

### چند پاک‌سازی: ترتیب معکوس

```python
@pytest.fixture
def res(request):
    request.addfinalizer(lambda: print("cleaned up 1"))
    request.addfinalizer(lambda: print("cleaned up 2"))
    request.addfinalizer(lambda: print("cleaned up 3"))
    return 1
```

خروجی بعد از تست:
```
3
2
1
```
**آخرین ثبت‌شده اول اجرا می‌شود** (مثل حالت stack). منطقش این است که آخرین چیزی که ساخته‌ای، اولین چیزی است که باید جمع شود.

### تفاوت با `yield`

این دو معادل‌اند:

```python
#  yield
@pytest.fixture
def res():
    r = create()
    yield r
    r.close()

#  addfinalizer
@pytest.fixture
def res(request):
    r = create()
    request.addfinalizer(r.close)
    return r
```

‏`yield` معمولاً خواناتر است، ولی `addfinalizer` در یک حالت مهم برتری دارد:

```python
@pytest.fixture
def two(request):
    a = create_a()
    request.addfinalizer(a.close)     # بلافاصله بعد از ساخت a ثبت شد

    b = create_b()                    # اگر اینجا خطا بیاید...
    request.addfinalizer(b.close)
    return a, b
```

اگر ساخت `b` خطا بدهد، `a.close` هنوز اجرا می‌شود چون قبلاً ثبت شده بود. در نسخه `yield` اگر خطا قبل از `yield` بیاید، کدهای بعد از `yield` اجرا نمی‌شوند و `a` باز می‌ماند. پس وقتی fixture چند مرحله‌ی پرریسک داریم، پاک‌سازی هر مرحله را **بلافاصله بعد از ساختش** ثبت میکنیم.

## `request.getfixturevalue("name")`

### مشکل

تا حالا fixture را با **نوشتن نامش در پارامتر** می‌گرفتیم. این نام باید از قبل ثابت باشد. گاهی نمی‌دانیم چه fixtureای لازم داری تا لحظه اجرا.
```python
import pytest

@pytest.fixture
def user():
    return {"name": "Ali", "age": 20}

def test_name(user):
    assert user["name"] == "Ali"
```

از عبارت `user` به عنوان fixture در تست هایی که داریم استفاده میکنیم 

### راه‌حل: فراخوانی با رشته بجای نام

```python
import pytest

def pytest_addoption(parser):
    parser.addoption("--slowdb", action="store_true", default=False,
                     help="use slow database")

@pytest.fixture
def fast_db():
    return "fast"

@pytest.fixture
def slow_db():
    return "slow"

@pytest.fixture
def db(request):
    if request.config.getoption("--slowdb"):
        return request.getfixturevalue("slow_db")
    return request.getfixturevalue("fast_db")



def test_db(db):
    print("db =", db)
    assert db in ("fast", "slow")
```


تست فقط `db` را می‌گیرد و نمی‌داند پشتش کدام fixture است.

```bash
pytest -s              # db = fast
pytest -s --slowdb     # db = slow
```

(اینجا از `default=False` استفاده شده تا اگر گزینه `slowdb--` را در `pytest_addoption` ننوشته باشیم خطا ندهد.


### مثال: انتخاب fixture با پارامتر

```python
import pytest

@pytest.fixture
def cat():
    return "meow"

@pytest.fixture
def dog():
    return "woof"

@pytest.fixture(params=["cat", "dog"])
def animal(request):
    return request.getfixturevalue(request.param)

def test_sound(animal):
    print(animal)
```

دو اجرا: یکی با `meow` و یکی با `woof`. اینجا `request.param` یک **نام fixture** است و `getfixturevalue` آن را به مقدار تبدیل می‌کند. (این ترکیب قدم ۴ و قدم ۵ است.)
```bash
pytest -v -s
```
خروجی:
```
test_animal.py::test_sound[cat] meow
PASSED
test_animal.py::test_sound[dog] woof
PASSED
```


‏pytest تست را دو بار اجرا می‌کند، چون `animal` دو مقدار در `params` دارد.

**اجرای اول**

1. ‏`request.param` برابر رشته `"cat"` است.
2. ‏`request.getfixturevalue("cat")` یعنی «fixtureای به نام `cat` را بساز و مقدارش را بده».
3. ‏`cat` مقدار `"meow"` برمی‌گرداند، پس `animal` هم `"meow"` می‌شود.
4. تست `meow` را چاپ می‌کند.

**اجرای دوم**: همین مراحل، با `"dog"` و `"woof"`.



## tips

| قاعده                   | توضیح                                                                                   |
| ----------------------- | --------------------------------------------------------------------------------------- |
| فقط fixtureهای در دسترس | همان قاعده جستجو: همان فایل، `conftest.py`، پلاگین                                      |
| نه در مرحله پاک‌سازی    | بعد از `yield` یا داخل finalizer نمی‌توانی fixture جدید بخواهی                          |
| scope باید سازگار باشد  | fixture با scope بزرگ‌تر نمی‌تواند fixture با scope کوچک‌تر را بخواهد (همان قاعده قبلی) |

### چرا همیشه از آن استفاده نکنیم؟

چون `getfixturevalue` وابستگی را **پنهان** می‌کند. اگر نام در پارامتر باشد، با `pytest --fixtures-per-test` و `setup-plan--` می‌توان آن را دید ولی با `getfixturevalue` در لحظه اجرا ساخته می‌شود و pytest از قبل نمی‌داند.
